# 极简修仙 · 风险修炼模式（原工程内可玩）

本模式是可切换的玩法改造，**默认旧模式不变**；不替换 Pygame 800×600 的既有界面、按钮位置、素材与布局。

## 启动

在项目根目录执行：

```bash
pip install -r requirements.txt
python main.py --risk
```

旧模式仍使用 `python main.py`。也可通过环境变量 `JIXIAN_MODE=risk` 启动新模式。

## 操作

正常状态下沿用 UI 的四个按钮位置，从左到右依次为**吐纳 / 收功 / 炼丹 / 渡劫**；走火时前三个按钮切换为**破心魔 / 静心 / 化为资源**，必须选一个再继续。新模式将原“气血/仙力”的进度条文字改为“寿元/配额”（位置及素材保持原样）。

## 已确定的原数值（不改）

| 规则 | 数值 |
|---|---|
| 吐纳倍率 | ×1 → ×7 |
| 对应走火率 | 0%、5%、10%、15%、22%、30%、40% |
| 每境修炼次数 | 12 |
| 每境可炼丹数 | 6 |
| 渡劫成功率 | 50% + 丹药 × 17%，上限 100% |
| 渡劫失败 | 本境前 2 次免扣修为，第 3 次起扣当前修为 50% |

走火按**尝试进入的倍率**判定。收功收益按 `10 × 倍率²` 计算。炼气升筑基需 100 修为，筑基升金丹需 250 修为。结成金丹获胜，寿元不足以继续渡劫或无法再完成一次吐纳+收功且未达到门槛则失败。

## 新增成本（首轮平衡参数，后续可调）

| 行为 | 成本/效果 |
|---|---|
| 每次吐纳 | 消耗 1 修炼次数和 1 年寿元 |
| 收功 | **额外消耗 1 修炼次数**；必须留出 1 次配额用于收功 |
| 炼丹 | 消耗 40 修为和 2 年寿元 |
| 渡劫 | 消耗 3 年寿元；**投入的所有丹药一次性消耗**，无论成功与否 |
| 每境寿元 | 22 年，突破刷新 |
| 突破 | 寿元、修炼次数和炼丹配额刷新；丹药清空 |

三颗丹药的理论成功率为 101%，实际按 100% 判定，但购买三丹需要 120 修为与 6 年寿元，不再是免费最优解。即便免扣修为，前两次渡劫失败仍会消耗 3 年寿元和全部投入丹药。

## 灵气潮汐（每轮收功或解决心魔后更新，提前公开）

- **平稳灵息**：不额外加成。
- **灵气奔涌**：达到 ×4 再收功，额外获得 60 修为。
- **丹火旺盛**：达到 ×3 再收功，下一次炼丹费用减少 20 修为，优惠不可累加。
- **固本培元**：达到 ×5 再收功，恢复 2 年寿元，不能超过上限。

潮汐在玩家作出吐纳决策前出现在日志及状态栏。走火率本身**不会因为灵潮而暗改**。

## 心魔三选一（新增试验参数）

- **破心魔**：耗 1 丹药，保留走火前的全部连击修为。
- **静心**：不额外耗资源，保留走火前一半连击修为。
- **化为资源**：放弃本轮修为、耗 2 年寿元和 1 次炼丹配额，换 1 颗丹（不能突破每境总配额）。

## 测试

无需启动 Pygame 的规则单测：

```bash
cd versions/v2.0-enterprise
python -m unittest discover -s tests/unit -p 'test_risk_run.py' -v
```

建议重点游玩：多次 ×2 收功、低剩余修炼次数时走火、丹火优惠一次性消耗、前两次渡劫失败、两次突破后的胜负状态。

## 兼容性

本模式是可选规则集；老的 `core/game_core.py`、`actions.py`、`rules.py`、`core/tide_system.py` 不变，旧存档/旧流程不自动迁移到本模式。所有新增成本和潮汐阈值可在 `core/risk_run.py` 独立调整。
